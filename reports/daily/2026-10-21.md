# 企业级 Agent / AI Worker / DataAgent 行业雷达

日期：2026-10-21  
类型：增量日报  
观察窗口：2026-10-19 11:35 至 2026-10-21 10:55（北京时间；以来源标示的发布日期和状态为准）

## 今日结论

本窗口的主线不是“又多了几个模型可选”，而是企业 Agent 正在同时补齐两类容易被忽略的生产能力：**受监管业务的控制面**，以及**多步长任务的推理控制面**。前者以 Google 的 `Gemini for government services` 为例：把 skills、现有系统连接器、记录级权限、引用、审批和合规控制面放入同一 Preview 产品，而不是把通用聊天入口直接套到高风险流程。后者以开源 `llm-d 1.0` 为例：将上下文复用、实时与后台任务隔离、队列配额和滚动升级下沉到推理服务层。

对 Coding Agent，两个更直接的运维信号同时出现：Google Antigravity 将 Claude Opus 5.5/Sonnet 5.5 放进企业模型选择器，但须由管理员启用、按量计费并受 spend limit 约束；GitHub 则一面将 Copilot 模型策略 API 推到企业/团队/应用/组织四层 GA，一面完成一批旧模型的实际停用。二者共同提醒：模型“已在产品页出现”、策略“已配置”、用户“在客户端看得到”、任务“实际路由到某个 model ID”是四种不同状态，不能互相替代。

本期没有新的基础模型正式发布。固定复查 OpenAI GPT/Codex、Anthropic Claude、Google Gemini、DeepSeek、通义、豆包、混元、Kimi、GLM 的官方入口后，未发现可与已记录发布并列的新 P0 模型状态。GPT-6 Astra 的正式发布、API/产品入口、工具、上下文、价格和安全边界已在 9 月日报完成核验，本期不因页面持续可见重复计分。

## Top Signal

### 1. llm-d 1.0：把长任务 Agent 的会话、异步队列和升级风险下沉到推理控制面｜89 分

**可验证事实**：Google Cloud 于 10 月 20 日宣布发布开源、Kubernetes 原生的 `llm-d 1.0`；公告称它是由 Google、Red Hat、IBM 等共同发起的 CNCF Sandbox 项目。1.0 包括多租户优先级/公平流控、v1 API、路由高可用与零停机更新、session-aware routing、turn-priority scheduling，以及原生 Responses API state。新增的 `llm-d-async-processor` 可从 Pub/Sub 或 Redis 等队列接收异步请求，按可用容量、优先级和配额与实时流量共用资源。[Google Cloud 公告](https://cloud.google.com/blog/topics/ai-infrastructure/llm-d-1-0-an-open-source-stack-for-distributed-inference)

**产品判断**：这是 Agent Infra 的实质变化，因为多步工作流的瓶颈常常不在单次生成，而在上下文反复装载、后台循环挤占交互流量、共享 GPU/TPU 的租户争用，以及滚动升级中断长会话。它不解决 Agent 的工具授权、流程编排、业务结果正确性或成本归因；公告里的 TTFT、吞吐、缓存命中率等数值来自所列工作负载或基准，不能外推为任意模型和业务场景的 SLA。

**启示**：自托管或可控推理平台应以“任务会话”而非“单一请求”观测：解析模型、session 路由、前缀/KV cache 命中与层级、队列等待、优先级、配额、加速器池、版本迁移、重试与最终结果都应关联。否则在长任务 P95 恶化时，团队无法判定是 Agent 步骤变多、路由失去上下文、后台任务抢占还是模型本身退化。

**建议动作**：选取一个交互式、多轮、带后台批处理的真实任务，在相同模型与工具权限下比较“普通 Service 路由”和“会话/优先级/异步隔离”。度量任务完成率、P50/P95 首 token 与端到端耗时、cache 命中、GPU/TPU 利用率、排队取消、跨版本会话失败、单位成功任务成本和人工接管；为升级定义 drain、回滚及超时任务恢复演练。

### 2. Gemini for government services Preview：行业 Worker 开始把“连接、权限、引用、审批”作为产品本体｜85 分

**可验证事实**：Google Cloud 于 10 月 21 日推出 `Gemini for government services`，明确为 **Preview**。官方列出五类组成：政府工作 skills、安全连接器、合作伙伴 agents、统一治理控制面和开放伙伴生态。公告称连接器在既有系统中查询、不迁移数据，并继承既有身份、角色和记录级权限；控制面包括 VPC Service Controls、CMEK、Assured Workloads 与引用输出。案例型工作流包含 FOIA 发现、批量脱敏、供应商评标和费用审计，并说明关键步骤由人员审批。[Google Cloud 公告](https://cloud.google.com/blog/products/ai-machine-learning/gemini-for-government-services/)

**产品判断**：这里真正值得跟踪的不是“政府版聊天机器人”，而是把业务技能、系统-of-record、最小权限、引用和人工责任放在同一产品边界。它仍是 Preview；公告所列连接器、伙伴能力、FedRAMP High Data Boundary 部署和合规适用性均不能推断为所有机构默认可购、可开或已验证。

**启示**：岗位型 AI Worker 的价值证据要拆成：流程规则怎样固化为可版本化 skills；数据是迁移、复制还是原地查询；身份与记录权限如何继承；哪些动作必须审批；每次结论如何带引用、如何回写系统，以及谁对最终结果负责。只验收“能做出一份答复”不会暴露越权、误引用、审批绕过或回写失败。

**建议动作**：在低风险、只读优先的跨系统流程中建立验收集。要求逐笔保留输入授权、读取范围、skill/规则版本、引用、建议动作、审批人、回写结果与异常原因；另外测量授权拒绝正确率、引用定位准确率、人工推翻率、超时恢复和权限变更后的残留访问。

### 3. Antigravity 引入 Claude 5.5：多模型选择与账单/权限控制必须一起验收｜84 分

**可验证事实**：Google Cloud 于 10 月 20 日宣布 Claude Opus 5.5 与 Claude Sonnet 5.5 已在 Google Antigravity 面向 Google Cloud 客户提供。管理员启用后，开发者可在 Antigravity 2.0、CLI 及 VS Code、JetBrains IntelliJ、Visual Studio 扩展的模型选择器中使用；这不是 Claude 原厂模型的新发布。对于 Gemini for business，伙伴模型按 pay-as-you-go 计费，不消耗 Gemini Enterprise Standard/Plus 的 pooled monthly token quota，管理员须配置 overage billing、spend limits 并授权模型。其 subagent 可指定 `inherit`、`flash` 或 `pro` 层级；背景 Gemini 协调也会消耗 first-party tokens，可能产生费用。[Google Cloud 公告](https://cloud.google.com/blog/products/ai-machine-learning/claude-opus-55-and-claude-sonnet-55-available-in-antigravity)

**产品判断**：这是一项企业 Coding Agent 的多供应商模型入口扩展，并非“所有人默认拥有 Claude”的声明。把跨模型审查作为可选工作流可能减少同一模型自审的盲点，但不自动保证代码正确、测试充分、成本更低或敏感数据边界一致。

**启示**：多模型 harness 至少应记录五层状态：管理员授权与地区/套餐、任务实际 model ID、子 agent 路由、背景协调模型及 token、模型与工具的实际花费。若这些字段无法关联到 commit、测试和最终接受人，就无法评价“更强模型”究竟提高了什么，也无法在异常账单或模型弃用时定位受影响任务。

**建议动作**：先用只读代码检索、测试失败分类与独立 diff 审查等低副作用子任务做交叉模型试验。固定输入、权限、超时和预算，比较单模型与双模型流程的缺陷检出、误报、重试、人工接受率、端到端耗时和全量账单；未通过基线前，不将自动审查结果当作合并批准。

### 4. Copilot model policy API GA：模型允许列表可进入变更管理，而不是只靠控制台｜82 分

**可验证事实**：GitHub 于 10 月 19 日宣布 Copilot model policies 的 GET/PATCH REST API 已 GA，覆盖 enterprise、enterprise teams、agent apps 与 organizations 四个层级。企业可在 organization mode 委派模型控制给组织，或在 enterprise teams mode 委派给团队与应用。[GitHub Changelog](https://github.blog/changelog/2026-10-19-copilot-model-policy-api-for-enterprise-orgs-and-teams/)

**产品判断**：这让允许/禁用模型的策略可以进入 IaC、代码评审和漂移检测，但 API 写入成功不等于客户端已经刷新、更不等于某个 Coding Agent 任务已解析到正确模型。它还不能代替套餐、费用、模型迁移评测和工具权限治理。

**启示**：模型策略应像 IAM 或网络策略一样管理：按企业—团队/应用—组织层导出快照，评审可追溯变更，检测本地配置与控制面漂移，并以客户端或任务日志闭环验证实际可用性。

**建议动作**：建立“策略提交—API 回读—客户端可见—任务实际 model ID”的四段自动检查。对模型弃用、敏感仓库、自动 PR 和高成本模型分别定义审批主体、默认拒绝、例外期限与回滚策略。

### 5. Copilot 已实际停用一批模型：迁移窗口已关闭，替代模型需要重新回归｜81 分

**可验证事实**：GitHub 于 10 月 19 日确认，Gemini 3.7 Flash、GPT-5.5、GPT-5.4、GPT-5.4 mini、GPT-5 mini 与 Grok 4.5 已在多数 Copilot 体验中停用，影响 Copilot Chat、inline edits、ask/agent modes 和 code completions。建议替代分别为 Gemini 3.8 Flash、GPT-6.1 Sol、GPT-6 Luna 和 Grok 4.7；Enterprise 管理员可能需要在 model policies 中启用替代模型，并在设置及模型选择器核验可见性。[GitHub Changelog](https://github.blog/changelog/2026-10-19-github-copilot-models-deprecated-on-october-19-2026)

**产品判断**：这是已经生效的生命周期事件，不应与 10 月 15 日那批“11 月中旬将停用”的公告混淆。厂商建议的替代并不是行为、价格、速率、工具调用或评测结果等价的承诺；固定模型的 prompts、脚本和交付基线都可能受到影响。

**启示**：模型策略 API 与停用公告组合起来，意味着组织可以把供应商模型生命周期变成可执行的迁移 runbook，而不是事后排障：先发现依赖、确认策略、做黄金集回归、观察线上任务，再完成替换。

**建议动作**：立即盘点固定 model ID、预设 prompts、Copilot CLI/app/IDE 自动化及文档中的旧模型；对替代模型检查策略启用、实际可见、成本、工具/输出契约、测试与安全扫描，保留异常任务的降级或人工接管通道。

## Agent 开发平台

本期没有确认 AWS Bedrock AgentCore、Microsoft Agent Framework/Foundry、Google ADK/Agent Platform、火山 AgentKit/VeADK 的新 GA 或普遍可用范围变化。`Gemini for government services` 的 Preview 值得作为平台设计参考：其架构把技能、连接器、治理与引用放在一个可管理边界内，但其行业、地区和 Preview 状态不能外推到通用企业租户。

对所有开发平台，建议将“平台已经提供连接器”与“某个 Agent 已获数据权限并成功完成流程”分开。前者是产品能力，后者需要租户配置、身份映射、数据授权、工具调用和业务验收共同证明。

## 数字员工 / AI Worker

本窗口没有确认豆包工作、Qoder、Claude Cowork、Kimi Work、Manus、Genspark 等通用工作 Agent 的新增 P0 普遍可用事实。Google 的政府产品却给出一个清晰的行业 Worker 边界：用于检索、脱敏、评标、审计等高风险事务时，输出要带来源，关键步骤要由人批准，数据与权限仍留在系统-of-record 的既有治理内。

因此，数字员工的“端到端完成”应拆解为可审计阶段：收件/读取、事实提取、规则判断、建议、审批、回写、通知和异常升级。任何阶段的执行失败、权限拒绝或人工改写都应是可统计的业务事件，而不能被单一任务完成率掩盖。

## DataAgent

Google 同期宣布 GDC air-gapped 的 enterprise search capabilities 进入 **Preview**：官方描述为完全在物理安全边界内运行的托管 RAG search，不连接公共互联网或 Google Cloud 全球基础设施。[Google Cloud 公告](https://cloud.google.com/blog/topics/hybrid-cloud/managed-rag-search-inside-the-sovereign-perimeter-gemini-on-gdc-enterprise-search) 这是部署边界的重要信号，但不是对所有数据源、模型、地区、硬件和合规资格的普遍承诺。

高敏 DataAgent 的问题不只是“模型能否回答”，还包括索引是否离开可信边界、连接器的身份与增量同步是否正确、引用能否定位、离线环境如何打补丁、模型/embedding 更新如何回归、以及断网/索引失败时如何恢复。Preview 更应先验证这些运行条件，而不是先承诺替代人工数据分析。

## 通用工作 Agent / Agentic Coding

Antigravity 的伙伴模型接入与 Copilot 的策略/停用事件共同揭示：一个企业 Coding Agent 的模型状态至少包括供应商已支持、组织已授权、入口已更新、任务实际选中、账单已归属和产物已验收。任何一层缺失，都可能出现“管理员认为已经开通，但开发者看不到”“开发者能选到模型，但预算未覆盖”“任务完成但回归未通过”等假完成。

建议把跨模型工作流设计为可验证的双人制而非魔法配方：执行模型负责实现，独立模型或规则工具负责审查，最终仍以测试、静态分析、依赖/许可证检查和人工接受为准。不同模型家族的差异应在同一评测任务中测量，而不是从供应商描述推断。

## 基础模型与 Agent Infra

本期未确认新的基础模型正式发布；六维复查结论如下：

| 维度 | 本窗口确认的增量 | 不能外推的边界 |
| --- | --- | --- |
| 工具/异步调用 | llm-d 1.0 新增队列型异步处理器与容量/优先级控制 | 不等于任一模型 API 新增工具能力 |
| 上下文与长任务 | session-aware routing、KV cache 及滚动升级面向长会话 | 不证明业务长任务成功率或成本必然改善 |
| Coding/Browser/Computer Use | Antigravity 扩展伙伴模型至 Coding Agent 入口 | 不等于所有账户、工具或数据默认可用 |
| 延迟/吞吐/成本 | llm-d 提供可组合的流控与缓存机制；Antigravity 明确伙伴模型按量计费 | 厂商工作负载数字和价格不构成组织 SLA/总成本 |
| API/产品开放范围 | Copilot 模型策略 API GA；GDC RAG 与政府服务均为 Preview | GA API 不等于策略已生效；Preview 不等于普遍可用 |
| 安全与治理 | 政府产品列出权限继承、VPC SC、CMEK、Assured Workloads、审批和引用 | 产品声明不替代本组织权限/合规/审计验证 |

llm-d 是本期最接近 Agent Infra 核心的发布，因为其确实跨越上下文/长任务、异步执行、延迟吞吐、升级治理多个维度，并有一手发布依据；但它是推理服务栈，不是基础模型新发布。

## AI 与模型平台 / AI 基础

企业控制面的最低闭环可归纳为：

- **声明层**：允许的供应商、模型/版本、区域、预算、工具和数据域；
- **授权层**：企业—团队/应用—组织策略、身份映射及管理员变更记录；
- **执行层**：任务实际 model ID、子 agent、工具调用、上下文/队列状态、token 与费用；
- **验收层**：测试/引用、人工接受、异常、回滚和模型停用迁移。

Copilot 的策略 API 能改善第二层自动化，Antigravity 的多模型入口扩展了第一、三层的复杂性，llm-d 则提供执行层的部分调度能力。四层缺任一层，Agent 的“已开通”都无法构成可运营交付。

## 风险与反信号

1. Google 的政府服务与 GDC enterprise search 均为 Preview；不得写作 GA、普遍可用或已满足所有合规要求。
2. `llm-d 1.0` 的性能、生产流量和客户引述来自官方公告所列环境；任何自建集群仍需独立压测、故障演练和成本核算。
3. Antigravity 的 Claude 接入取决于管理员授权、overage billing、spend limit、伙伴模型条款和产品入口版本；“模型可选”不等于零附加成本或默认开放。
4. Copilot 的策略 API GA 不代表所有客户端立即刷新或每个任务使用目标模型；必须回读策略并查看客户端/任务日志。
5. 10 月 19 日的 Copilot 模型已经停用，建议替代模型不保证输出、工具、时延、成本和安全评测等价。
6. GitHub Search 的 `large-language-model` 限定查询受匿名 rate limit 影响未完成；热度发现不作为成熟度结论，待下次恢复额度后补扫。
