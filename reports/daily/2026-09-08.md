### 1. GitHub Agentic Workflows：安全边界从可选运行时走向显式迁移计划｜观察，不计分

**可验证事实**：GitHub Agentic Workflows 9 月 7 日周更回顾了 `v0.88.4` 的可信 enclave 敏感度控制、GitHub App 工作流的数据流完整性/保密性（DIFC）策略生成、`aw.json` 项目支持和 Linear/Jira 定时 smoke test；相应 GitHub Release 显示该版本由 `github-actions` 于 9 月 4 日发布，且标记为 pre-release。[周更](https://github.github.com/gh-aw/blog/2026-09-07-weekly-update/) · [v0.88.4 Release](https://github.com/github/gh-aw/releases/tag/v0.88.4)

**产品判断**：这是一条值得追踪的开源 Agent Runtime 治理路线，但不是本窗口的新正式版本。其有价值之处在于把“Agent 能否运行”拆成网络/工具访问、数据流策略、可信执行环境和失败分类四个可操作控制点；pre-release 状态则意味着不能据此推导生产稳定性。

**启示**：企业治理面不宜只做静态 Tool Allowlist。对于会读取仓库、发起网络请求或创建 PR 的自动化任务，还应明确数据从何处流入、可流向何处、哪些输出是被策略安全拒绝，以及拒绝后在运营面显示为“跳过”还是“执行失败”。

**建议动作**：将其列入 Agent Runtime Watchlist。若后续出现 GA、迁移截止日期、Cloud Hypervisor 的普遍可用范围变化，或新的策略执行/审计接口，再以该新增状态建立正式事件卡。

### 2. Cloud Hypervisor 成为 GitHub Agentic Workflows 的推荐 microVM 方向｜已知迁移，继续观察

**可验证事实**：9 月 5 日公告称 `gvisor` 与 `docker-sbx` runtime 将弃用，新的硬件虚拟化隔离路径为 `cloud-hypervisor`；默认 `docker` runtime 仍可用并保留网络隔离与代理强制。Cloud Hypervisor 当时处于 Preview，仅适用于带 `/dev/kvm` 的 GitHub-hosted Ubuntu x86_64 runner。[官方迁移公告](https://github.github.com/gh-aw/blog/2026-09-05-cloud-hypervisor-consolidation/)

**产品判断**：运行时选型的关键不应简化为“哪个隔离更强”。这是一个约束组合：任务是否需要硬件虚拟化边界、Runner 是否满足 KVM 条件、网络代理和镜像固定是否可审计、以及从旧 runtime 迁移时是否能重现原有行为。

**启示**：把执行环境纳入 Agent 任务合同：`runtime profile、硬件条件、网络出站策略、镜像/资产摘要、工具权限、数据敏感度、降级策略`。环境不满足时应可控地退回默认 profile 或阻断，而不是悄然改变隔离等级。

**建议动作**：为高风险工作流补一条预检：检测宿主是否具备 KVM 和所需网络策略；同时把 `gvisor`、`docker-sbx` 的存量引用纳入迁移清单。由于公告早于本观察窗口，本期不把它写入事件数据。

### 3. AWS AgentCore 的九月文档更新：评测框架与用户授权仍是平台重点｜待精确日期核验

**可验证事实**：AWS 的 AgentCore Release Notes 当前列有 TypeScript Agent Framework 评测支持、Identity Consent Portal、MCP server 作为 Gateway target 及 MCP server 开发支持；文档页面按“September 2026”归组，但未在这些单项中给出可用于本窗口判定的发布日期。[AgentCore Release Notes](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/release-notes.html)

**产品判断**：这些条目共同覆盖评测、代表用户授权和工具互联，是企业 Agent 平台的关键接口；不过没有精确日期就不能把页面当前内容等同于过去 24—48 小时的新发布，也不应据此声称已覆盖所有框架或账户。

**启示**：对厂商的滚动文档，数据模型应允许 `published_at=unknown` 与 `first_seen_at` 分离。只有 Release Note、公告、版本标签或变更日志给出可核对的生效时间后，再进入日报增量及评分。

## 今日建议深挖

建立一张“运行时迁移卡”，用于每一次 Agent Sandbox、模型或 Tool Gateway 变更。至少包含：`变更来源与发布日期、旧/新 profile、适用 runner/区域、隔离与网络差异、身份和密钥边界、可调用工具、迁移前置条件、回退方案、回归任务集、审计字段、Preview/GA 状态`。

**验收标准**：任选一个长任务，能够在迁移前后比较完成率、工具调用拒绝原因、网络/权限失败、人工介入、成本和外部副作用；若环境不满足条件，系统能明确阻断或回退，而非静默降低隔离等级。
