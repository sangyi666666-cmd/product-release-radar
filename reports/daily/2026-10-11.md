# 企业级 Agent / AI Worker / DataAgent 行业雷达

日期：2026-10-11  
类型：增量日报  
观察窗口：2026-10-09 00:00 至 2026-10-11 08:59（北京时间；以来源标示的发布日期和状态为准）

## 今日结论

今天的高价值增量集中在三个“控制面”而不是新模型本身：Coding Agent 的默认模型和 MCP 启动时机开始可以由企业显式约束；Google 进一步把旧的 Gemini Code Assist 商业入口导向 Antigravity；DataAgent 的区域和模型可用性则继续按具体 endpoint 演进。对生产团队而言，迁移、默认值和工具启动都不是体验细节：它们会直接改变模型选择、工具暴露、计费归属、日志覆盖与回退责任。

开源侧，OpenSandbox 1.1.1 是一条应优先处理的运行时补丁：它修复了 1.1.0 server wheel 无法 import 的发行问题，并新增身份绑定文件操作、租户隔离与更明确的代理错误语义。它不证明任意 Agent 已安全隔离；尤其 release 自身明确说明文件身份校验不是租户边界，仍需把调用方身份、挂载、网络、凭证和 Kubernetes namespace 隔离一起验收。

本次已扫描 GitHub Trending，以及 `llm`、`ai-agent`、`large-language-model` 三个 topic 在过去 7 天仍有更新的仓库。去重并排除归档、镜像和明显非 AI 候选后，未发现可由 README、Release 或维护者公告核验、且未在近 7 天日报重复的更高价值版本事件；Stars、Forks 和短期提交均未被写成产品成熟度。

## Top Signal

### 1. GitHub Copilot for JetBrains 增加企业默认模型和 MCP 自动启动控制｜83 分

**可验证事实**：GitHub 于 10 月 10 日发布 Copilot for JetBrains 更新。企业管理员现在可通过 managed settings 为新会话选择任一可用的 Copilot agent model 作为默认模型，但用户仍保有显式 model picker 选择。新增 MCP 设置可关闭 Copilot 和 Claude 的 MCP server 自动启动；同一更新还宣布 JetBrains IDE 2025.1 不再受支持，需要 2025.2 或更高版本。[GitHub Changelog](https://github.blog/changelog/2026-10-10-new-controls-and-chat-improvements-in-copilot-for-jetbrains/)

**产品判断**：默认模型和“工具何时被启动”终于成为可配置的企业策略面，但这不是对模型、MCP server 或其工具权限的统一审批。默认模型只影响新会话起点；用户可选择其他模型。关闭自动启动也不等于禁止 MCP、阻断网络、回收已发出的令牌，仍需配合 server allowlist、身份委派、网络策略与审计。

**启示**：Agent 产品应分别记录并呈现：组织默认值、用户覆写、工具注册、工具激活、实际调用和外部副作用。把这些状态合并成一个“已开启 MCP”会掩盖授权与数据路径差异，也无法在事故后复原实际执行环境。

**建议动作**：在一个低风险 JetBrains 项目做策略演练：设置组织默认模型、允许用户覆写、关闭 MCP 自动启动，再分别验证新会话、已存在会话、手动启动 server、无效 server 与切换账户的真实行为和日志。验收应含模型/工具实际选择、网络端点、访问令牌、拒绝原因和回退步骤。

### 2. Google 停止销售新的 Gemini Code Assist 订阅，现有订阅将在 2027 年停止自动续订｜82 分

**可验证事实**：Google Cloud 的 10 月 9 日 Release Notes 写明：自该日起，新的 Gemini Code Assist Standard 与 Enterprise 订阅不能再购买；现有订阅可在 2026 年余下时间自动续订，但自动续订将在 2027 年结束。官方建议替代开发工具为符合条件 Gemini Enterprise 订阅和 Gemini Enterprise Agent Platform 中的 Antigravity；该页也说明 Antigravity/Antigravity CLI 是其统一的多 Agent 平台方向。[Google Cloud Release Notes](https://docs.cloud.google.com/gemini/docs/release-notes)

**产品判断**：这是商业可得性和产品入口的迁移信号，不是 Antigravity 已自动等价替换每一项 Gemini Code Assist 功能、地区、价格、合同或数据处理条款的证明。现有客户“可续订到 2026 年末”也不等于新购、扩容、附加席位或 2027 年后的续约路径不受影响。

**启示**：企业 Agent 的供应商迁移不能只做模型质量对比，还应建立“合同—身份—IDE/CLI—MCP/连接器—知识/记忆—日志—预算—数据地域—退出”清单。尤其当产品入口并入更大的 Agent 平台时，原来的席位、角色、管理员控制和审计留存可能分属不同对象。

**建议动作**：立即盘点订阅开始/续费日期、许可证分配、依赖的 IDE/CLI 工作流、连接器和日志保留要求；先以只读代码任务进行双轨试点，再决定迁移节奏。任何停用旧入口的计划都需有可复放任务集、权限回收、导出留档和人工回退，不应以产品公告代替验收。

## 重点信号

### 3. BigQuery Data Engineering Agent 扩展至东京区域 endpoint，并支持 Gemini 3.5 Flash｜76 分

**可验证事实**：Google Cloud 在 10 月 9 日的全局 Release Notes 中列出，BigQuery Data Engineering Agent 已可在 `asia-northeast1`（东京）regional endpoint 使用，并支持 `gemini-3.5-flash` 模型。[Google Cloud Release Notes](https://docs.cloud.google.com/release-notes/)

**产品判断**：这是 DataAgent 的部署位置和模型选项增量，并未公布所有区域、所有数据源、全部操作类型或所有组织套餐的普遍可用性。特别是“东京 endpoint 可用”不能推导为数据、日志、模型推理、跨区域查询和恢复产物都会自动保持在同一地域；这些由具体服务配置、连接器和组织策略共同决定。

**启示**：DataAgent 的区域验收至少应拆成控制面所在地、数据读取/计算所在地、模型推理和日志/审计所在地，以及跨区域失败时的行为。模型可选项也应与 KPI 定义、SQL/Python 产物、成本、上下文、引用和权限拒绝分别测量。

**建议动作**：针对东京 endpoint 建立一组不含敏感数据的可复跑任务：语义发现、SQL/代码生成、执行失败、权限不足、跨区域对象和人工接管。记录实际地域、模型、查询/计算账单、输出引用、审计日志与降级路径后，再评估是否进入受控生产试点。

### 4. OpenSandbox 1.1.1 修复 1.1.0 安装故障，并补齐身份文件操作、代理与多租户边界｜75 分

**可验证事实**：OpenSandbox 于 10 月 9 日发布 stable `release-1.1.1`。Release Notes 指出，`1.1.0` 的 `opensandbox-server` wheel 因缺少 FastPath gRPC stubs 而在 import 时失败，PyPI 包不可原地替换，官方建议所有 1.1.0 用户升级。1.1.1 还为五种 SDK 提供显式 Linux UID/GID 的文件操作接口，增加隔离 session 的多 overlay mount；在 Kubernetes 共享 namespace 场景为标记租户的 sandbox 增加可见性隔离；并把代理后端超时与中途响应故障分别映射为 504/502。Release 同时明确，身份文件 API 仅执行文件权限检查，并非租户隔离边界。[OpenSandbox 1.1.1 Release](https://github.com/opensandbox-group/OpenSandbox/releases/tag/release-1.1.1)

**产品判断**：这是一项应处理的 Agent sandbox 运行时可靠性与防护更新，不是“升级即安全”的认证。升级会改变 HTTP 错误码和部分 SDK 的默认重试表现；共享 namespace 的旧未标记 sandbox 仍有兼容期行为，身份文件 API 的 UID/GID 选择也必须留在可信后端。

**启示**：Sandbox 必须以“运行时身份 + 文件系统 + 挂载 + 网络出口 + 凭证 + 租户资源可见性 + 生命周期”构成完整隔离合同。单一 shell/container 成功运行、单一 UID 参数或单一 HTTP 状态码都不足以证明跨租户和跨工具路径安全。

**建议动作**：若使用 1.1.0，优先在隔离环境升级到 1.1.1；回归 import、创建、暂停/恢复、snapshot、网络代理超时、后台命令和 SDK 重试。另以两个租户、两个 UID、受限目录、受限凭证及异常重启测试实际拒绝和审计证据；把 502/504 的告警和重试策略按 SDK 分别核对。

## Agent 开发平台

Copilot for JetBrains 的新控制强化了“默认模型”和“工具激活”可由企业管理的方向。实际控制效果受许可证、IDE 版本、组织设置和 MCP server 自身配置共同影响；本期没有确认 AWS Bedrock AgentCore、Microsoft Foundry、Google ADK/Agent Platform、火山引擎 AgentKit 或阿里云 AgentCore 在窗口内的其他高价值 P0 新发布。AWS AgentCore 的十月 Release Notes 项目未提供精确到日的发布日期，因此不把“October 2026”条目强行归入本窗口。

## DataAgent

东京 endpoint 与 Gemini 3.5 Flash 的组合为 Data Engineering Agent 提供了可核验的部署/模型选择增量，但仍缺少对跨数据源权限、语义层版本、执行产物、地域边界和费用的统一公开承诺。应将这类记录看成试点候选，不将单一 region 更新写作企业级 DataAgent 成熟度证明。

## 通用工作 Agent / Agentic Coding

Copilot for JetBrains 的企业默认模型、模型选择器、MCP 自动启动和 IDE 版本退役需要放在同一次升级评估中：模型选择影响会话起点，MCP 启动影响工具暴露时点，IDE 退役影响客户端兼容性。它们均不能替代仓库权限、分支保护、CI、安全扫描、代码审查和合并/回滚责任。

## 基础模型与 Agent Infra

本窗口没有确认新的基础模型正式发布。OpenSandbox 1.1.1 是 Agent Infra 的运行时更新：它同时涉及安装可用性、运行时身份、租户可见性、网络代理与错误恢复，故纳入重点观察；但其性能、隔离和安全声明仍需在目标操作系统、Kubernetes 版本、挂载、身份源和网络策略下独立复测。

## 风险与反信号

1. 企业默认模型不等于锁定模型，用户覆写、会话存量和不同客户端可能产生策略差异。
2. 关闭 MCP 自动启动不是网络隔离或权限回收；已配置 server 的令牌、缓存和手动启动路径需要另测。
3. Code Assist 停售与 Antigravity 推荐之间存在功能、合同、地域和迁移计划的待核验空档，不能用“替代”代替迁移验收。
4. Data Engineering Agent 的区域 endpoint 和模型名不能单独证明数据驻留、跨区域读取、日志留存和结果可审计。
5. OpenSandbox 1.1.1 的身份文件 API 不是租户安全边界；共享 namespace、挂载、代理、secret 和后端身份源仍须分别强制。

## 今日建议深挖

1. **Coding Agent 工具激活矩阵**：将默认模型、用户覆写、MCP 注册/启动/调用、网络、凭证和审计记录放入同一测试矩阵，验证每项策略的实际拒绝与回滚。
2. **开发工具入口迁移账本**：为 Gemini Code Assist 相关用户建立合同日期、许可证、工作流、模型、工具、数据地域、日志和退出方案清单，再进行可复放双轨试点。
3. **Sandbox 边界回归集**：围绕 OpenSandbox 1.1.1 做跨 UID、跨租户、跨挂载、代理超时和重启恢复测试；验收失败路径，不只验收正常命令完成。
