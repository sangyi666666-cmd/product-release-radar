# 企业级 Agent / AI Worker / DataAgent 行业雷达

日期：2026-08-31  
类型：首期基线日报  
观察窗口：重点关注 2026-08-24 至 2026-08-31，同时补充建立行业基线所需的重要信息

## 今日结论

行业竞争已经从“谁能搭一个 Agent”转向“谁能让大量 Agent 安全、可控、可评测地进入生产”。Agent 身份、Registry、权限策略、评测、运行观测和成本控制正在成为企业平台的标准底座。

DataAgent 正从问答和 Text-to-SQL 演进到多步分析、工具和函数调用、代码执行、可视化、报告与行动闭环；可信语义层、权限和可追溯证据比单纯模型能力更重要。

数字员工平台开始以垂直岗位和端到端工作为中心。HR、财务、法务、IT 等领域的 SaaS 厂商依靠业务数据、流程和权限体系形成差异化，通用 Agent 平台则在加速补齐治理和行业模板。

## Top Signals

### 1. Databricks Genie Agent 的可编程和工具化能力进入 GA

**事实**：8 月 27 日，Genie Agent 的 Agent Mode API 和可视化结果 API 进入 GA；作者可以把 Unity Catalog 标量函数和表值函数挂载为 Agent 工具。8 月 25 日，Genie One 的 macOS 桌面应用进入 Beta。[Databricks 2026 年 8 月发布说明](https://docs.databricks.com/aws/en/release-notes/product/2026/august)

**判断**：DataAgent 不再只是数据平台内的聊天界面，而是在成为可被其他应用、定时报表和多 Agent 系统调用的分析能力单元。

**启示**：DataAgent 的产品形态应同时支持“给人使用的问数入口”和“给其他 Agent 使用的数据分析工具/API”；两者共享语义、权限、评测和审计底座。

**建议动作**：梳理当前 HR/财务 DataAgent 是否具备稳定的 API、结构化输出、图表结果返回、函数工具和任务级审计。

### 2. Snowflake 把代码执行、评测版本和 Skill 扩展推入生产能力

**事实**：8 月 26 日 Cortex Agents Coding Agent GA，Cortex Extension 可在 Agent Skill 中引用；8 月 21 日 Cortex Agent / Analyst 的评测版本定向 GA；8 月 20 日 Agent 代码执行工具进入 Preview，可在隔离沙箱中运行 Python 进行计算和可视化。[Snowflake 2026 功能更新](https://docs.snowflake.com/en/en/release-notes/new-features-2026)

**判断**：领先 DataAgent 平台正在把“SQL 查询”“Python 分析”“Skill”“评测”整合成统一生命周期。报告生成能力的上限将由可控代码执行和证据链决定。

**启示**：报告生成不要只依赖 LLM 文本总结，应将数据查询、计算、图表和文字结论拆成可验证步骤，并保留版本化评测。

**建议动作**：为 HR/财务报告场景设计一套“查询结果—计算脚本—图表—结论—引用”的 Trace 结构。

### 3. AWS 提出“分级自治”，治理从静态审批转向动态权限

**事实**：AWS 8 月 26 日提出 Graduated Autonomy：Agent 根据持续可靠性获得更高权限，表现下降时收回权限；其 AgentCore 以 Runtime、Gateway、Policy 和 Evaluation 支撑这一模式。[AWS 架构博客](https://aws.amazon.com/blogs/architecture/closing-the-ai-agent-trust-gap-with-graduated-autonomy/)

**判断**：企业 Agent 权限不会长期停留在“只读或全自动”的二元选择，未来更像员工授权：按任务、风险、历史表现和审批规则动态分级。

**启示**：数字员工平台应把自治等级作为产品对象，至少区分“只建议、执行前确认、低风险自动、高风险禁止或升级”。

**建议动作**：选择一个 HR 和一个财务任务，制定自治分级矩阵及升级/降级条件。

### 4. Google 继续把数字员工做成“行业系统”，而非通用聊天助手

**事实**：Google 8 月 25 日发布 Gemini Enterprise for Legal，强调专业 Skill、业务系统连接、权限隔离、机密性和治理，覆盖合同审查、监管扫描、法律研究等任务。[Google Cloud 官方博客](https://cloud.google.com/blog/products/ai-machine-learning/introducing-gemini-enterprise-for-legal)

**判断**：数字员工的竞争壁垒来自行业上下文、流程控制、专业评测和责任边界。这个模式同样适用于 HR 与财务。

**启示**：HR/财务 AI Worker 应围绕岗位工作包建设，包括专属 Skill、数据权限、规则、证据、审批和升级路径，而不是堆叠通用问答能力。

**建议动作**：选定一个 HR 岗位，按 Job → Task → Skill → Tool → Rule → Human Review 建立工作模型。

### 5. 开源 Agent Builder 正在补沙箱、Skill 和持久工作区，但企业级问题随之暴露

**事实**：Dify 1.16 引入新的 Agent 体验，包括 Linux 沙箱、Skill、Agent Roster 和 Workflow 集成；1.17 反馈中出现权限隔离、Skill 包上传、持久工作区和发布后数据迁移等问题。[Dify Releases](https://github.com/langgenius/dify/releases)、[Dify 1.17 反馈](https://github.com/langgenius/dify/milestone/37)

**判断**：开源平台正在从对话/工作流 Builder 走向可执行 Agent 平台，但沙箱安全、权限、多租户、持久状态和生命周期仍是生产化难点。

**启示**：Agent 开发平台可借鉴开源产品的 Builder 和 Skill 体验，但平台核心竞争力应放在企业身份、权限、稳定运行、评测运营和内部生态复用上。

**建议动作**：对照 Dify 新 Agent 的能力，做一次“可借鉴体验 / 不可直接复用的企业底座”双栏评审。

## Agent 开发平台动态

### Microsoft Copilot Studio

8 月指导中心新增 AI 模型生命周期管理内容；2026 年以来产品持续强化 Agent 评测、活动图、模型选择、A2A、MCP、计算机操作、Agent Inventory 和 Entra Agent ID。[Copilot Studio What's New](https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new)、[指导中心更新](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/whats-new)

产品信号：企业平台的重点从 Builder 扩展到“模型生命周期 + Agent 生命周期 + 组织级治理”。

### Salesforce Agentforce

Salesforce 已将新 Agentforce Builder 作为唯一的新 Agent 创建入口。新架构以图和子 Agent 为核心，Agent Script 将自然语言推理与确定性表达式结合，并配套测试套件和 Scorer。[Salesforce 迁移说明](https://developer.salesforce.com/blogs/2026/08/migrate-legacy-agents-to-the-new-agentforce-builder)

产品信号：企业 Agent Builder 正在从自由 ReAct 循环走向“图编排 + 状态 + 确定性规则 + 回归测试”。

## 数字员工 / AI Worker 观察

## 补充专题：通用工作 Agent 与 Qoder 产品矩阵

### 豆包工作

8 月 25 日，豆包工作作为面向生产力场景的独立 Agent 产品与品牌正式发布。它可以围绕目标拆解任务、调用工具并持续推进，覆盖文档、表格、PPT、图片、视频、网页和应用等工作产物；经授权后可操作浏览器与电脑，也可借助云电脑在本机关闭后继续执行，并支持手机远程推进任务。其企业差异化来自与飞书上下文和权限体系的打通，以及技能、连接器和多专业 Agent 协作。[新华网发布信息](https://www.news.cn/tech/20260825/1c13b806a0a946a9981e95f0c238e98c/c.html)、[豆包 App 官方产品页](https://apps.apple.com/cn/app/%E8%B1%86%E5%8C%85/id6683305962?mt=12)

**产品判断**：豆包工作的竞争单位不再是一次问答，而是“理解企业上下文—完成跨工具任务—交付可编辑产物—持续沉淀知识”的完整工作闭环。

**启示**：HR/财务场景应优先建设可直接交付的工作产物、跨系统执行和权限继承，聊天入口只是表层；同时需要明确企业知识回写、可编辑交付、云端续跑和远程接管的边界。

**建议动作**：选取“月度经营分析”或“人力结构分析”，用同一套数据与验收标准实测其任务拆解、数据处理、Office 产物质量、引用可追溯性和人工修订成本。

### Qoder 全系列

Qoder 已从 AI 编程工具扩展成跨终端、跨角色的 Agentic 工作平台。当前官方产品矩阵包括：

| 产品层 | 产品 | 主要角色 |
|---|---|---|
| 交互与开发入口 | Qoder、Qoder IDE、JetBrains Plugin、Qoder CLI、Qoder Mobile、Qoder Voice | 从桌面、IDE、终端和移动端发起、接续与监督任务 |
| 通用工作执行 | QoderWork | 本地文件处理、数据分析、文档生成、浏览器/电脑操作、定时任务、IM 与 Skill 扩展 |
| 托管运行与嵌入 | Qoder Cloud Agents、Qoder Agent SDK | 在托管沙箱运行长任务，或将计划、工具、权限、记忆和会话能力嵌入自有产品 |
| 数字员工 | QoderWake | 管理具有身份、记忆、技能、权限和工作区的 Waker，支持对话、定时/事件/API 自动任务及多 Waker 工作流 |
| 安全治理 | Qoder Security | 面向代码与 Agent 执行过程的安全能力 |

产品矩阵以官方产品页和文档为准；QoderWork 虽未出现在新版首页的主产品导航中，但仍有独立文档与发布记录，因此纳入全系列观察。[Qoder 产品矩阵](https://qoder.com/new-qoder)、[QoderWork 文档](https://docs.qoder.com/qoderwork/introduction)、[QoderWake 文档](https://docs.qoder.com/qoderwake/overview)、[Cloud Agents 文档](https://docs.qoder.com/cloud-agents/overview)、[Agent SDK 文档](https://docs.qoder.com/cli/sdk/overview)

**产品判断**：Qoder 正在形成“个人工作入口—开发者工具—托管 Runtime—可嵌入 SDK—常驻数字员工”的纵向全栈。QoderWake 最值得跟踪的不是角色模板，而是数字员工对象与运行设备解耦、长期能力沉淀、自动触发、多 Agent 编排和权限边界如何共同落地。

**启示**：Agent 开发平台和数字员工平台不宜割裂建设。底层应复用 Agent Harness、Skill/连接器、会话和任务状态、权限、记忆、沙箱与评测；上层再分别提供开发者入口、知识工作入口和岗位型数字员工入口。

**建议动作**：以 Qoder 产品矩阵为参照，画出当前能力分层图，标注“已有、缺失、重复建设、需要统一底座”四类状态；优先验证 QoderWake 的 WakerFlow、自动任务、记忆治理和 IM 协作。

### 同类产品对比

| 产品 | 核心定位 | 执行环境与入口 | 最值得关注的差异 |
|---|---|---|---|

## DataAgent 产业基线

- Microsoft Fabric Data Agent 已 GA，并进入 Microsoft 365 Copilot，强调受治理的数据源和 Entra 权限；SDK 正迁移到 Responses API。[Fabric What's New](https://learn.microsoft.com/en-us/fabric/fundamentals/whats-new)、[Data Agent SDK](https://learn.microsoft.com/en-us/fabric/data-science/fabric-data-agent-sdk)
- Google Conversational Analytics 已在 BigQuery 和 API 进入 GA，可通过 SDK、API、MCP 和 ADK 嵌入应用或多 Agent 系统，依赖 Looker 语义层和 BigQuery 上下文。[Google Cloud 综述](https://cloud.google.com/blog/products/data-analytics/conversational-analytics-in-google-data-cloud-in-q326)
- Databricks Genie Agent Mode 已从单轮问数升级为多步研究、引用、图表和支持表，并开始开放可编程 API。[Genie Release Notes](https://docs.databricks.com/gcp/en/ai-bi/release-notes/2026)
- Snowflake Cortex Agents 将 Cortex Analyst、Search、代码执行、Skill、预算与评测整合为受治理的 Agent Runtime。[Snowflake Cortex Agents](https://www.snowflake.com/en/blog/enterprise-ai-agent-platform/)
- 开源方向中，WrenAI 强调受治理语义上下文和可分享的 SQL/图表，Vanna 强调用户感知、访问控制和多数据库，DB-GPT 强调私有化 Data Agent 与工作流。[WrenAI](https://github.com/idcdog/wrenai)、[Vanna](https://vanna.ai/)、[DB-GPT](https://github.com/eosphoros-ai/DB-GPT)

## 优先启示与建议

### P0：建立可信生产底座

1. Agent Registry 与统一身份；
2. 任务级权限、审批和自治等级；
3. 离线评测、在线监控、版本对比和回归；
4. 全链路 Trace：上下文、计划、工具、数据、输出、人工动作；
5. 成本、延迟、成功率、风险和业务价值统一看板。

### P0：把 DataAgent 从问数升级为可复用分析能力

1. 指标与业务语义层；
2. 澄清、规划、查询、校验、分析、报告的多步链路；
3. SQL、Python、图表和引用可追溯；
4. 同时支持人用 UI 和 Agent 用 API / Tool；
5. HR / 财务高风险数据和结论的权限、脱敏与人工确认。

### P1：从场景功能升级为岗位型 AI Worker

先选择一个高频、跨系统、结果可衡量、风险可控制的岗位任务，建立 Job → Task → Skill → Tool → Rule → Evaluation → Human Escalation 模型，再抽取平台共性。

## 风险与反信号

- 开源项目的功能发布速度不代表生产成熟度，权限、状态、升级和多租户问题必须单独验证；
- 厂商案例中的 ROI 多为选择性披露，不能直接用于内部立项测算；
- DataAgent 的 Demo 准确率不能替代真实指标口径、权限和多轮业务问题评测；
- “多 Agent”不是价值本身，只有在任务可分解、边界清晰且评测可控时才应采用。

## 今日建议深挖

用一个真实 HR 或财务岗位任务，制作第一张 AI Worker 工作模型：

```text
业务结果 → 任务步骤 → 所需数据 → Skill/Tool → 决策规则 → 风险等级
→ 自动化级别 → 人工确认点 → 成功指标 → 失败与升级路径
```

这会成为后续比较 Workday、SAP、Oracle、ServiceNow、豆包工作、QoderWake 等产品的统一框架。
